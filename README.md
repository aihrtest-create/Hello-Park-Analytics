# Hello Park Analytics Web Dashboard

## Обзор архитектуры
Это локальное веб-приложение (написанное на Flask и Vanilla JS), которое генерирует отчеты в форматах `.xlsx`, вытягивая сырые данные из базы **InfluxDB** через публичный API **Grafana** (stat.hello.io).

Так как API публичный, **VPN больше не требуется**.

### Структура проекта
* `backend/` — Сервер на Python (Flask).
  * `app.py` — Главный роутер (endpoints). Принимает запросы с фронтенда и вызывает нужные скрипты генерации.
  * `reports/common.py` — Базовые настройки (Токены, URL Grafana `https://stat.hello.io`, список парков, функции вычисления дат). **Это самое важное место для правки общих конфигураций.**
  * `reports/avatars.py` — Логика детального отчета (Pivot таблицы по дням).
  * `reports/conversion.py` — Логика отчета по воронке "Аватар -> Первое Задание".
* `frontend/` — Веб-интерфейс пользователя (HTML/CSS/JS). Дизайн основан на современному подходе Glassmorphism.

## 📊 Доступные отчеты
На данный момент в приложении реализованы два основных отчета:

1. **Привязка Аватаров (`avatars`)** 
   - **Метрика**: `AvatarLinkedInHome`
   - **Формат**: Таблица с датами месяца по строкам и парками по столбцам.
   - **Особенности**: Внизу таблицы генерируется блок с формулами. Пользователю достаточно вписать цифры в желтую строку "Кол-во проданных билетов", и Excel автоматически рассчитывает `Activation rate` для каждого парка.

2. **Конверсия "Аватар → Первое задание" (`conversion`)**
   - **Метрики**: `AvatarLinkedInHome` и `AchievementCounted`
   - **Специфика**: Запросы используют предварительную фильтрацию по уникальному `id` пользователя, чтобы избежать искусственного завышения процентов (т.к. задания могут выполняться много раз).
   - **Формат**: Компактная таблица с итогами за выбранный месяц (Парк | Создано аватаров | Хотя бы одно задание | Конверсия %).

## 🛠 Как добавить новый отчет (Памятка для ИИ-ассистента)

Если вы начинаете новый чат для доработки системы, просто следуйте этим 3 шагам:
1. **Создайте логику**: Создайте новый файл в `backend/reports/название_отчета.py`. Опишите в нем логику Flux-запроса через `requests` и сборку данных через `.to_excel()` (как это сделано в соседних скриптах).
2. **Зарегистрируйте в бэкенде**: Откройте `backend/app.py`, импортируйте вашу новую функцию генерации и добавьте новое условие (`elif report_type == "название_отчета":`).
3. **Добавьте кнопку в UI**: Откройте `frontend/index.html` и скопируйте блок `<label class="report-card">...`, поменяв `value` на `название_отчета` и добавив красивое описание.

## Как запустить приложение локально
```bash
python3 -m backend.app
```
Затем перейдите по адресу http://localhost:5000 в браузере.
