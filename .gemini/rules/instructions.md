Этот файл содержит глобальные инструкции для ИИ-ассистента по работе с данным проектом.

---

## 1. Обзор проекта и архитектура
Проект **Hello Park Analytics** представляет собой локальное веб-приложение (Flask на бэкенде, HTML/CSS/JS с дизайном Glassmorphism на фронтенде), предназначенное для выгрузки аналитики из базы данных **InfluxDB** через **Grafana API** и генерации форматированных отчетов в формате Excel (`.xlsx`).

* **Бэкенд:** `backend/app.py` (роуты Flask)
* **Бизнес-логика отчетов:** `backend/reports/`
* **Конфигурация Grafana/InfluxDB:** `backend/reports/common.py` и файл `.env` в корне проекта.

## 4. Специфика и типы отчетов

### А. Популярность игр и ачивки (`compare_avatars_camp.py`, `generate_lfl_report.py`)
* **Трафик/Сканирования браслетов:** событие `PlayerEnteredInstallation` (группировка по `zone`).
* **Легкие ачивки (TimeSpent):** событие `AchievementUnlocked` с фильтром по `name =~ /TimeSpent/`.
* **Средние ачивки / Выигрыши (GameWin):** событие `AchievementUnlocked` с фильтром по `name =~ /GameWin/`.
* **Сложные ачивки / Действия (GameAction):** событие `AchievementUnlocked` с фильтром по `name =~ /GameAction/`.
* **Like-For-Like (LFL) логика:** Сравнение темпов роста только по старым паркам, которые были активны в предыдущем году (`AVIAPARK`, `DUBAI`, `MEGA`, `RIVIERA`, `VLADIKAVKAZ`), с исключением новых парков для чистоты метрик.

### Б. Привязка Аватаров (`avatars`)
* **Метрика:** `AvatarLinkedInHome`.
* **Формат отчета:** Даты по строкам, парки по столбцам.
* **Формулы:** Внизу таблицы добавляется расчет `Activation rate` (отношение привязанных аватаров к проданным билетам, которые пользователь вписывает вручную).

### В. Конверсия "Аватар → Первое задание" (`conversion`)
* **Метрики:** `AvatarLinkedInHome` и `AchievementCounted`.
* **Важно:** Фильтровать по уникальным `id` пользователей, чтобы избежать дублирования из-за повторных прохождений квестов.

### Г. Глубина заданий (`quest_depth`)
* **Метрика:** `AchievementCounted` (общее число ачивок и число уникальных активных пользователей).
* **Показатели:**
  1. `Базис заданий` — фиксированное число квестов парка по книге `Achievements for server.xlsx` (без «Башен», минимум между Space2 и Voxels).
  2. `Средняя глубина (заданий)` — среднее число выполненных квестов на активного гостя.
  3. `Индекс охвата (%)` — отношение средней глубины к базису парка ($\frac{\text{Глубина}}{\text{Базис}} \times 100\%$).

## 5. Инструкции по добавлению новых отчетов
При добавлении нового типа отчета:
1. Создать скрипт логики в папке `backend/reports/имя_отчета.py` с использованием `requests` (Basic Auth / API token) и `pandas`.
2. Зарегистрировать новый обработчик в `backend/app.py` (роут `/api/generate`).
3. Добавить соответствующую карточку выбора в пользовательский интерфейс `frontend/index.html`.

## 6. Правило деплоя и продакшн-окружения (КРИТИЧНО)
* **Официальный продакшн URL:** `https://party.hello-park.io/analytics/`
* **Категорически запрещено:** использовать, упоминать или создавать скрипты под Timeweb (`194.87.118.33`, `nip.io` и др.). Старый VDS Timeweb выведен из эксплуатации и не существует.
* **Как устроен деплой:**
  1. Приложение развернуто в Docker на корпоративном сервере `party.hello-park.io`.
  2. Папка аналитики синхронизируется в репозиторий `DR-construct-Mega/analytics` (`https://github.com/aihrtest-create/mega.git`).
  3. Пуш в ветку `main` репозитория `mega` автоматически триггерит вебхук обновления и пересборку Docker-контейнера на `party.hello-park.io`.
  4. Для деплоя в один клик используется локальный скрипт `./deploy.sh`, который копирует `backend`, `frontend`, `requirements.txt` в `DR-construct-Mega/analytics` и пушит в `main`. Изменения также коммитятся и пушатся в текущий репозиторий `Hello-Park-Analytics`.
